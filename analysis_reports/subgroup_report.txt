METHOD (uptake scoring, per with-trace):
  (a) tool_use events invoking the skill: name=='Skill' OR serialized input
      contains '.claude/skills' or 'SKILL.md'. (Nudge text in the prompt
      also contains 'SKILL.md' but lives in user/queue-operation lines,
      so tool_use-only counting is uncontaminated.)
  (b) count of distinctive SKILL.md literals found anywhere in the trace.
      Literals are 8-12 per skill, auto-extracted (code lines, inline code,
      >=4-word phrases, version pins), then filtered: dropped if verbatim in
      >=2 other study skills' SKILL.md (boilerplate), dropped if present in
      ANY of the same task's 3 without-skill traces (task-derivable, not
      skill evidence), blacklist (semver links etc.), containment dedup.
  (c) tool_use inputs referencing bundled skill files (scripts/ plus other
      resources: matched by 2-component path suffix e.g. 'office/pack.py',
      or distinctive basenames >=12 chars). Only xlsx ships scripts/;
      turborepo ships references/*.md; add-admin-api-endpoint ships 3 .md
      reference files. (c) generalizes 'scripts/' to all bundled resources.
  Class: STRONG if a>0 or c>0; WEAK if only b>=2; else NONE.
  'ing' column = skill content verifiably ingested into the trace (b>=2);
  STRONG traces with ing=no are 'attempted-only' engagements (glob-only
  searches or failed Reads of the skill path).

Reading: BOTH-uptake pairs show the HIGHEST internal SIP/divergence rate,
NEITHER pairs are intermediate (and still above the without-without floor),
and mixed ONE pairs are lowest. This does NOT match the naive story that
mixed pairs drive the elevated null-plus level; instead, pairs where both
runs engaged the skill differ from each other the most (skill engagement
appears to add its own run-to-run variability), and even no-detectable-
uptake with-runs diverge more than without-runs (consistent with the 58-
vs-9 skill-description context difference, or with heavier-tailed with-run
behavior). Groups are task-confounded (e.g., BOTH is dominated by
add-admin/bash-defensive/turborepo; NEITHER contains xlsx), so treat these
splits as descriptive only.

------------------------------------------------------------------------------
5. CAVEATS
------------------------------------------------------------------------------
- This subgroup analysis is POST HOC: uptake classes were defined after
  seeing the headline (null-adjusted) results, and the STRONG/WEAK/NONE
  thresholds (a>0 or c>0; b>=2) were chosen by us, not preregistered.
- Uptake is not randomized: traces that engage the skill may differ from
  non-engaging traces in other ways (e.g., longer, more exploratory runs),
  so the STRONG-vs-NONE contrast is correlational, not causal.
- The 9 treatment pairs per task share 3 with- and 3 without-traces, so
  pair-level observations are dependent; all inference here is at the task
  level (n = number of tasks in the subgroup), which is small.
- Literal extraction (b) is heuristic; false negatives possible when a
  model paraphrases skill guidance, false positives when a model
  independently produces a skill-like string not seen in the 3 without
  traces (a finite leakage control).
- Observed b values are bimodal (0 vs 8-12): literal matches arise from
  the SKILL.md body being echoed into the trace after a successful read,
  so (b) behaves as a read-verification signal here. No trace adopted >=2
  literals without an explicit read (WEAK class is empty), i.e. we found
  no evidence of skill-content adoption without reading the file.
- Treatment differs from control by more than the study skill: with-runs
  had 58 installed skills (descriptions in context), without-runs had 9.
  Any description-level influence (from the study skill's or the 57
  others' descriptions) is invisible to our uptake metrics and would land
  in the NONE subgroup. This is a study-design confound to acknowledge in
  the rebuttal, independent of this subgroup analysis.
- Metric (c) extends 'scripts/' to all bundled skill resources because
  only xlsx ships a scripts/ directory.
- Bootstrap CIs resample tasks (10k, seed 20260728) and are percentile CIs;
  with few tasks in a subgroup they are unstable and should be read as
  descriptive.
